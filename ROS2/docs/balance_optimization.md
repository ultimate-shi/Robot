# 实机通信与自动平衡优化

本次只修改 ROS，保留 STM32 固件及串口协议。控制管理器以 20 Hz 交换缓存，不代表三块板都达到 20 Hz。DMC0 默认 10 Hz，DMC1 默认 6 Hz，SE2 的 U 默认 20 ms 刷新、f 默认 6 Hz 查询。周期超限后不补发积压周期。

## 通信与保护

- 三块板各由一个线程独占；普通关节目标只有一个最新缓存，串口读取完成后重新取最新目标。动作服务交给轮板线程，取消服务使用优先槽，撤销尚未执行的定距请求；正在执行的事务完成后处理停车。
- `read/write` 只交换快照，不等待串口、ROS 发布或线程退出；硬件状态与诊断由 `telemetry_rate=10 Hz` 的独立回调发布。查询失败、真实反馈超过 `feedback_timeout_ms`、U 间隔达到 `servo_watchdog_ms` 都锁定输出，通知各板独立停车；生命周期退出和人工恢复才等待线程结束。
- DMC1 保留 T 活动期间不发逐轴 D、动作租约、心跳及四轴 D0 停车。T 响应丢失即使停车成功也锁定，避免无法确认的旧动作重新运行。
- SE2 单线程负责 U/f，无两个线程争抢串口；U 的看门狗间隔按 `tcdrain` 后的单调发送时刻计算，不使用 ACK 完成时刻。串口流水只进入有界队列，由状态回调发布，队满丢弃最旧日志并增加 `serial_trace_dropped`，不能让可靠 ROS 发布反压保活。20 ms 是周期调度目标，单次 f 查询可能使本轮执行超过 20 ms；应以真实 U 间隔是否达到 100 ms 判断看门狗风险，不能把 `cycle_overruns` 等同于看门狗超限。f 响应可能阻塞 U；若实际间隔触及固件期限，报告故障，不能把独立线程当成期限保证。故障或上游超时只发中性值。
- 激活和恢复从实测位置初始化、轮速清零；第一次控制器缓存写入再次清除旧目标。恢复后需确认控制器状态，不自动恢复任务或开启平衡。
- 超声波只在收到新 f 样本时发布，时间戳反映真实采样年龄。关节广播可以重复缓存；实机平衡另外要求 `/diagnostics` 中 DMC0 的真实反馈年龄有效，硬件失能时暂停调节。
- 正常关闭和可用反馈下的故障退出尽力保持腿部最近实测角度；串口断开或反馈失效时无法保证腿板接受新的保持指令，此时锁定并要求现场检查。

异步频率和保护期限位于 `robot_hardware/config/hardware_bringup.yaml`，同名参数经实机、控制器和模型入口传递。`servo_watchdog_ms` 只用于监测现有固件期限，不修改固件。不要缩短串口超时来制造提速。

`/diagnostics` 新增 `robot_hardware/timing/DMC0`、`DMC1`、`SE2`，使用现有 DiagnosticArray 类型：

| 字段 | 含义 |
|---|---|
| `feedback_age_ms` / `feedback_sequence` | 成功查询后的真实样本年龄和序号，重复目标不能续期 |
| `command_sent_age_ms` / `sent_sequence` | 最近一次成功周期输出的年龄和对应目标序号；尚未下发时年龄为 -1 |
| `transaction_*` | 含同串口指令间隔及响应等待的单事务耗时 |
| `cycle_*` | 本板周期任务内查询、计算及输出的耗时；SE2 周期含本轮实际执行的 f 查询 |
| `cycle_overruns` | 周期执行时间超过配置周期的累计次数 |
| `u_gap_p99_ms` / `u_gap_max_ms` / `watchdog_overruns` | SE2 相邻 U 实际整行写出间隔及期限超限次数 |

耗时使用单调时钟；P50/P95/P99 取最近 1024 个样本，最大值、样本数及失败数为进程生命周期累计量。验收须比较窗口起止计数，不能把历史故障算成本轮新增故障。

## 平衡控制

参数位于 `robot_control/config/body_balance.yaml`。实机整车入口启用 `require_hardware_timing`；虚拟模式默认不要求硬件诊断。独立启动实机平衡时也必须传 `require_hardware_timing:=true`。

- 中档根据**实际腿角 + IMU 倾角**解算完整到位位置，`position_gain=1.0`；不再积分腿高小步，也不使用 3° 领先窗截断自动调平目标。每次从实测腿高重新求解，目标不靠上次指令累加。
- 四腿投影到同一支撑平面，去除单靠 roll/pitch 无法观察的对角扭曲。行程允许时保留公共高度；触及限位先平移公共高度，再整体等比例缩小不可达的姿态修正。IMU 只能观测车身姿态，不能证明轮子接地；非平面障碍上的接地判定仍需轮载/接触等反馈。
- `rate_prediction_s=0.06`：用角速度短时预测回正提前制动；`target_change_deg=0.5`：变化不足 0.5° 不重复下发，已经提交的目标由板端完成定位。
- 保持区进入阈值为 1°/0.03 rad/s，退出阈值为 1.5°/0.05 rad/s；保持区不再逐帧改写位置。IMU 新样本才参与新目标计算。
- `max_target_lead_deg=3.0`、`max_velocity_deg_s=30.0`、`max_acceleration_deg_s2=60.0` 继续用于低/高固定高度和回中轨迹；中档直接下发完整位置。
- 反馈中断暂停新目标，恢复时从实际腿角重建；超过两倍正常周期不补算大步。±30°、停止锁、硬件失能撤销平衡及过流保护保持有效，恢复不自动启用。
- `attitude_gain`、`rate_damping`、`kp`、`kd_pitch`、`kd_roll`、`derivative_window`、`max_step_deg` 保留旧参数兼容，中档不再使用旧速度积分算法。

## 持续驾驶输入

首页驾驶优先复用同源 `9100/robot/api/drive-stream` WebSocket，经同一个网关和 Unix Socket 转给控制台；地图、图像等 HTTP 请求不占用这条连接。浏览器仍每 100 ms 发送当前意图；连接未就绪时兼容原 `/api/drive`。重连不缓存/重放旧非零命令，断线立即清除该连接仍拥有的速度，350 ms 命令超时继续生效。松键、失焦、切页继续发送零速；发送缓冲忙时不积压移动帧，松键优先关流并通过 HTTP 补零速。已启用持续连接的页面用递增序号屏蔽迟到 HTTP/旧帧，旧 HTTP 页面原有多页面行为保留。

控制状态附加 `input_transport`、`input_age_seconds`、`input_fresh` 供排查续期缺口；不作为新的授权心跳。断开旧连接不会清除另一页面后来接管的输入。依赖 `python3-websockets`（容器）及网页虚拟环境的 `websockets>=10.4,<13`，Dockerfile 与安装依赖已同步。更新网关后需刷新浏览器以加载新输入链路。

## 采集与验收

先构建受影响包并运行测试，不能用尚未通过的插件替换运行实例：

```bash
colcon build --packages-select robot_description robot_hardware robot_control robot_main robot_web
source install/setup.bash
colcon test --packages-select robot_hardware
python3 -m pytest src/robot_control/test src/robot_hardware/test/test_protocol.py -q
ros2 launch robot_main robot.launch.py --show-args
```

只读采集工具不创建控制发布器，也不自动切换平衡：

```bash
python3 scripts/diagnostics/balance_latency_probe.py --duration 60 --phase idle --output calibration_reports/balance/idle.jsonl
python3 scripts/diagnostics/balance_latency_probe.py --duration 60 --phase balance --output calibration_reports/balance/balance.jsonl
```

JSONL 包含同一单调时轴上的 IMU、平衡目标与状态、真实关节角、硬件电流和诊断。配套 summary 记录实际到达频率及是否观察到平衡开启；`--phase idle` 期间若开启平衡，不能算关闭平衡的静止基线。旧插件没有新 timing 字段时明确记录不可用，不能推算为事务耗时。

按顺序验收：

1. 关闭平衡、停车并锁定软件停止，备份现有安装包和配置后切换插件。先观察静止通信，确认真实反馈年龄、8 个控制器状态和 U 间隔；不自动解除停止锁。
2. 现场具备防倾倒支撑后，人工解除停止并启用平衡。横滚、俯仰各做正负 3°、5°扰动，每组三次。撤除扰动后 5 秒内回到 ±1°，反向过冲 ≤ max(初始倾角的 30%, 1°)，保持区内观察 10 秒，无持续摆动。
3. 腿板完整周期 P99 < 80 ms，连续 10 分钟无新增失败，才验收 10 Hz。通过后另开测试窗口，以 `leg_io_rate:=20.0` 评估；要求 P99 < 40 ms、连续 10 分钟无新增失败。未通过则回到最近通过档位，平衡控制率先保持 10 Hz。
4. 用相同障碍、车速和方向记录峰值倾角、恢复时间、腿跟踪延迟、电流；超出机械行程的工况单独记录。不同工况不可直接当作优化前后对比。

底盘重启后，网页控制器状态查询超过既有 `controller_status_timeout` 会撤销本地等待并重试，迟到结果不能覆盖新请求。若需要单独重启控制台，追加 ROS 参数 `-p startup_stop_latched:=true`，保持软件停止锁；默认值仍为 false，普通启动行为兼容。

默认不启用平衡。现场扰动、越障和 20 Hz 验收未完成前，不宣称消除了实机摆动或已经达到 20 Hz。回退时先保持停止锁、停用新硬件实例，恢复备份安装包再启动旧实例，禁止两套插件同时打开同一串口。

2026-11-05 修正：原先 ACK 抖动被计入 U 发送间隔，且串口线程仍同步发布可靠日志。改为真实发送计时、日志解耦和 20 ms 刷新余量；固件期限仍为 100 ms，真实发送超时仍会锁定，不自动恢复。

网页状态查询超时与驾驶连接分别判断：仅当驾驶连接在服务端命令超时期内收到有效确认时，状态查询失败才保留当前按键；驾驶确认失效仍释放输入，后端命令超时保持不变。驾驶期间暂停下载新地图，日志只在日志页拉取，减少页面处理和网络争用。

腿板到位目标按实际发送的百分之一度整数逐通道去重：四腿均未变化时只查询反馈，部分变化时使用现有 R 协议的 32767 跳过未变化通道。成功确认后才记住目标，失败仍锁定；激活/人工恢复清空去重记录并从真实位置初始化。停止、故障退出保持强制提交四腿实际位置；上游超时只保持一次，不追随反馈微动重复定位。DMC0 的目标下发年龄只在真正下发时更新，静止保持期间持续增加属于正常现象，反馈年龄仍由每次成功查询更新。固件一次定位自身的执行超时保持不变，不以重复指令延长。
