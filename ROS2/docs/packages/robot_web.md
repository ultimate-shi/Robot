# robot_web 功能包

## 职责与入口

`robot_web` 将网页入口与控制台放在同一功能包。宿主机常驻的 `robot-web.service` 提供唯一的 9100 端口；整车启动时，`robot_main` 通过 `web_console.launch.py` 启动容器内的 ROS 控制台节点。两者通过工作区 `.runtime/robot-console.sock` 通信，不再开放第二个网页端口。

| 路径 | 用途 |
| --- | --- |
| `/robot/` | 手动驾驶、地图导航、相机和模式控制 |
| `/robot/api/navigation-status` | 当前导航规划、Nav2 Action 反馈与最终结果；导航控制区每 0.5 秒读取 |
| `/robot/status` | 机器人、导航、传感器与系统状态 |
| `/robot/console` | 终端式实时 ROS 输出 |
| `/log/` | `robot_logging` 的独立历史日志查询与 MCAP 下载 |
| `/v1/*` | 已有推理接口，由 9100 网关转发 |
| `/health` | 网页、日志与推理服务的健康状态 |

宿主机入口配置在 `config/web.yaml`，控制台 ROS 话题、手动命令超时、相机来源和可选模型接口在 `config/web_console.yaml`。静态页面位于 `web/`，ROS 节点和运动状态分别在 `robot_web/console.py` 与 `robot_web/control.py`。

## 控制安全

控制台无需网页心跳即可手动操作，且不设网页速度上限或独占控制权。多个页面同时操作时，最后到达的速度命令生效。松键和手动命令超时会停车。手动速度由控制台直接发布到 `/cmd_vel_safe`，绕过超声波避障；导航速度经 `/cmd_vel_console`、避障 `/cmd_vel_nav_safe` 后由控制台转发到 `/cmd_vel_safe`。底盘运动学、轮速保护和硬件故障保护仍生效。当前代码启动时软件停止锁初值为未锁定；显式软件停止会锁存停车，直到页面点击“解除软件停止”；它还会取消网页任务与导航目标，并阻止受整车锁约束的定距 Action，且不替代物理急停。
首页“首页 · 机器人控制”标题下方单独显示底盘提示，包括故障锁定、控制板不可用、心跳异常和反馈中断；过期反馈会明确标为过期，不以旧的输出状态显示为正常。
导航模式的“当前模式控制区”显示规划中、待确认、Nav2 已接受、导航中、成功、取消及失败状态。导航中按 Nav2 Action 反馈更新目标、剩余距离、剩余朝向、预计时间、已用时间和恢复次数；安全层告警单独显示，速度为零本身不再被认作安全层停车。接近目标后仍需满足 Nav2 的目标朝向容差；地图点击默认沿用选点时机器人朝向，定位不可用时需等待恢复再选点。反馈中断或位置和朝向持续无进展会提示检查。规划失败使用 Nav2 的错误码区分地图外、目标占用和无路径；导航结束保留时间与结果原因，迟到反馈不能覆盖新目标。
传感器状态中的超声波数量表示有效测距路数。若探头仍持续发布但距离为无效值，导航安全提示显示“测距无效”；完全断流或超时仍显示“测距过期”。两种情况都会保持对应方向的安全停车。
直行默认线速度为 0.06 m/s，低/中/高预设分别为 0.06/0.08/0.1 m/s。四轮均使用 D 模式曲线；低速档按架空双向跟速结果选定。低于曲线首点的目标从零点插值，精度尚未单独验收。

固定在真实环境中的相机数据默认不用于运动中的虚拟机器人。探索、跟随、视觉选目标和模型任务依赖相应地图、定位、检测或推理服务；不可用时页面应显示状态。外部模型为可选配置，模型任务需经过白名单和用户确认。

当前 `console.py` 的跟随启动校验引用了 `ControlState` 中不存在的 `linear_max`，因此跟随启动会报错；修复代码并复测前，不应将跟随入口视为已验收。


驾驶输入优先使用同源 `WS /robot/api/drive-stream`，与地图、图像 HTTP 连接分开，未就绪时兼容 `/api/drive`。连接断开立即释放本连接速度，350 ms 命令超时保留；重连不会重放旧按键。曾使用流的页面将忽略迟到的旧 HTTP/流序号，另一页面接管后不会被旧连接关闭误停车。状态 `control` 附加输入传输类型、年龄与新鲜度，供只读诊断。

## 车身姿态、头部与键盘

首页手动控制区提供“车身姿态”和“头部”两个面板。四腿滑块按左前、右前、左后、右后排列，显示与精确输入均为板端角度（°），选择 +15°/−15° 对应 DMC0 `R` 命令字段 +1500/−1500。该手动目标直接提交，不经过高度换算或网页端渐进角度；头部滑块仍限速。为保持上滑伸展、车身上移，左前/右后上滑时板端角度减小，右前/左后上滑时角度增大；ROS 与板端的角度方向由桥接器/硬件插件成对换算。“四腿回零”仅一次提交四条大腿的零位目标；头部面板“头部回零”仅一次提交水平/俯仰两个零位目标，两组独立，不控制轮子或转向。两种回零均不逐步递减，保留控制器、反馈、平衡及头部锁定检查；任一相关控制器不可用则整组不执行。回零可能收缩大腿。

键盘默认开启，仅首页手动模式且未编辑输入框/滑块时响应；大小写均支持，允许驾驶、姿态和头部组合操作。

| 按键 | 功能 |
| --- | --- |
| 方向键 | 前进、后退、左转、右转 |
| W / S | 前倾仅伸展后腿 / 后倾仅伸展前腿 |
| A / D | 左倾仅伸展右腿 / 右倾仅伸展左腿 |
| Q / E | 整体降低 / 升高，保留四腿高度差 |
| J / L | 左转头 / 右转头 |
| I / K | 抬头 / 低头 |
| 空格 | 停止当前手动运动，包括未完成的滑块目标；不锁存紧急停止 |

相反键抵消；倾斜组合累加伸展量。整体升降和倾斜分别按参与腿的剩余行程共同限幅，不能逐腿截断。保持的是理想几何高度差，真实地形、轮胎形变等造成的姿态误差仍需实机验证。整车启动将共享 `leg_length` 传入网页高度换算；独立启动时沿用 YAML 的 `leg_length_mm`。腿部按钮/WASDQE 每次提交一步，参与腿最大改变 5°，短按一步、按住每 0.3 秒重复一步（等角度起步时为 5、10、15、20）。在高度空间选择共同位移，倾斜时其他腿可少于 5° 以保留原高度差；先到限位的腿共同限制该动作。连续步进从上次目标累加，松开取消尚未发出的重复请求，已提交的一步继续到目标；空格可中止当前目标。旧持续意图接口兼容保留，头部继续按 15°/s 积分；其持续输入超时 0.35 秒停止并以有效反馈保持。失焦、切页、模式切换与禁用键盘清除输入并停止手动关节。网页断线不关闭独立运行的自动平衡。

自动平衡设置统一位于车身姿态面板：低/高档是固定高度，中档持续调平，横滚/俯仰目标默认限制 ±10°。平衡启用、设置确认中或状态未知时禁止手动大腿；虚拟模式没有平衡服务时可独立调腿。头部归中节点存在或锁定状态有效时禁止手动头部。大腿板端方向参数 `leg_hardware_sign=[-1,+1,-1,+1]` 必须与 `RobotSerialSystem` 的 R 映射一致；WASDQE 继续在高度空间联动，与单腿角度输入独立。默认关节限位为大腿 ±30°、头部水平 ±90°、头部俯仰 ±30°。

所有页签共用侧栏“紧急停止”。停止锁通过 `/web_console/stop_latched` 同时通知平衡与头部归中节点，平衡不会在解除后自动启用。头部归中暂停后，解除停止再点击“恢复建图/定位头部归中”，调用新增 `/mapping/resume_head_lock`（`std_srvs/Trigger`）显式恢复；暂停期间不发布头部就绪。缺失有效反馈时不猜测保持位置，页面显示未确认原因。

新增网页接口仍经 9100 网关与现有 Unix Socket：

| 接口 | 输入与结果 |
| --- | --- |
| `POST /robot/api/joints` | `group=leg/head`、完整 `values` 数组；`unit=deg` 保留 ROS 角度语义及限速；大腿新增 `hardware_deg`，按 FL/FR/RL/RR 四个板端角度直接提交；旧 `height_mm` 兼容保留 |
| `POST /robot/api/joints/zero` | `group=leg/head`、`client_id/sequence/generation`；一次设置对应组全部关节到 0°，序列屏障阻止旧持续输入覆盖 |
| `POST /robot/api/joint-step` | `action=w/a/s/d/q/e`，以及 `client_id/sequence/generation`；每请求一步，步长与重复间隔由 `leg_step_deg/leg_step_repeat_seconds` 配置 |
| `POST /robot/api/joint-motion` | `client_id`、递增 `sequence`、状态中的 `actuators.generation`，以及 -1～1 的 `pitch/roll/lift/yaw/head_pitch`；正值依次为前倾、左倾、升高、左转头、抬头；`hold=true` 取消未完成手动动作 |
| `POST /robot/api/body-balance` | `enabled/level/target_roll_deg/target_pitch_deg`；返回处理中，随后由状态确认，服务超时保持手动大腿锁定 |
| `POST /robot/api/head-lock/resume` | 显式恢复建图/定位头部归中，返回服务结果 |
| `GET /robot/api/status` | 增加 `actuators`（关节、限位、平衡、禁止原因）及 `camera_raw`；旧字段保留 |

状态页区别未收到、过期、无效和正常数据。Astra 分别观察 `/astra/color/image_raw`、`/astra/depth/image_raw` 与处理后图像，未打开预览也更新健康状态；未配置原始话题时显示“未配置”。双目模式继续显示左右目和计算深度。控制板已发现不代表实时通信正常，整车故障及输出不可用会影响关节有效状态。六个手动关节、其他轮子/转向关节、可用电流及 IMU/八路超声波均逐项显示；未实测的设备不能视为通过实机验收。

## 启动与验证

```bash
colcon build --symlink-install --packages-select robot_web
source install/setup.bash
ros2 launch robot_web web_console.launch.py --show-args
pytest -q src/robot_web/test
```

完整运动链应通过 `robot_main` 启动。只启动本包控制台时，不会自行启动底盘和避障节点。

网页状态查询超时与驾驶连接分别判断：仅当驾驶连接在服务端命令超时期内收到有效确认时，状态查询失败才保留当前按键；驾驶确认失效仍释放输入，后端命令超时保持不变。驾驶期间暂停下载新地图，日志只在日志页拉取，减少页面处理和网络争用。
