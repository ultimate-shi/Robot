# 三路里程计融合检查（2026-10-27）

## 结论

实机三维 EKF 的维度选择合理：视觉融合六维位姿，IMU 融合 roll/pitch 和三轴角速度，轮侧只融合 vx/vy/wz；不重复融合轮侧积分位置或视觉速度，也不积分 IMU 加速度求位置。统一入口中只有 EKF 发布 `odom -> base_link`。

旧配置遗漏了迟到测量的历史回放，已修复。单路短时中断可保持输出连续，但不能据此保证长期精度。四轮一致打滑和全部断流仍不能保证稳定、准确的 odom；输出新鲜不代表测量新鲜。

## 已修复：双目延迟

既有双目配置记录约 0.6～0.9 秒处理延迟，而旧 EKF 默认 `smooth_lagged_data=false`、`history_length=0`。robot_localization 3.8.3 的旧测量仍会执行校正，但不回退到采集时刻，因而旧视觉位置可能向后拉当前状态，或因创新过大而被拒绝。

- `state_estimation.yaml` 开启 `smooth_lagged_data=true`、`history_length=2.0`。
- 开启 `predict_to_current_time=true`，回放后预测到当前时刻。
- 保持 `permit_corrected_publication=false`，不重复发布历史时刻。
- `odometry_covariance_guard.yaml` 新增 `max_message_age=1.5` 秒和 `future_tolerance=0.1` 秒；过龄、明显超前、零时间戳、非有限位姿和无效四元数不进入 EKF。保留原采集时间戳，不将旧图像伪装为当前测量。
- 若调整最大视觉年龄，EKF 历史窗口必须更长并留出调度余量。超过窗口的积压帧应丢弃。

历史回放需要额外计算；本次轻载测试不能替代相机、导航同时运行时的 CPU、输出频率与延迟验收。`transform_time_offset` 和 `wait_for_transform` 均不能替代迟到测量补偿。

依据：安装版本 [robot_localization 3.8.3 的测量处理](https://github.com/cra-ros-pkg/robot_localization/blob/3.8.3/src/filter_base.cpp) 与 [历史回放和预测实现](https://github.com/cra-ros-pkg/robot_localization/blob/3.8.3/src/ros_filter.cpp)。

## 尚存限制：打滑

轮侧由实际反馈、腿角和转向角求平面速度，Huber IRLS 对单轮残差降权，硬异常剔除，少于三个有效轮时停发，并增大不一致情况下的协方差。这些保护有效，但有边界：

1. 四轮一起空转/同向打滑时，轮间残差可以为零，协方差也不会因此增大。
2. 实机轮速本身由同一编码器位置差分生成；位置变化与轮速一致不能证明轮胎对地无滑动。
3. EKF 创新门限不是打滑检测器。渐进偏差可能持续被接受；增大协方差也可能让门限更容易通过，不应只收紧门限解决。
4. `max_sync_skew` 参数目前没有用于实际时间差检查，状态中的 `sync_skew` 固定为零；轮侧消息没有保留各控制板的独立采样时间，不能把它当作已实现的同步保护。

后续应使用采集时刻对齐的视觉位移与轮侧积分做跨源一致性判定，疑似滑移时降低轮侧可信度；视觉同时失效时需按时间/距离限制自主运动。不能以当前时刻的轮速直接对比迟到的视觉。

## 尚存限制：断流与恢复

| 情况 | 当前实际行为与边界 |
| --- | --- |
| 视觉中断 | 轮速和 IMU 继续支持平面短时推算；xy/yaw 漂移，z/vz 缺乏独立约束；失去视觉前的垂直速度可能继续积分。 |
| IMU 中断 | 轮侧和视觉继续融合；快速转动和倾斜失去高频约束；无磁 Madgwick 在重启后需重新收敛。 |
| 轮侧中断或有效轮不足 | 视觉位姿变化仍能约束速度，IMU 不能提供线速度；视觉迟到时只能先预测再回放纠正。 |
| 全部中断，或只剩 IMU | EKF 可继续发布新时间戳的预测；缺乏平移测量时不能可靠判断停车，误差会增长。 |
| 数据恢复 | 会重新校正，可能产生修正跳变，或因长时间漂移而被创新门限拒绝；本次不保证长时间失效后的自动重获。 |

`sensor_timeout=0.2` 是全部测量停止更新后的纯预测触发条件，不是每路传感器的看门狗，也不会自动把 vx/vy/wz 置零。当前 `localization_guard` 检查融合输出的新鲜度、协方差、TF 和视觉处理心跳，并提供有界跟踪预算，但没有逐路监督轮侧/IMU 新鲜度；融合输出本身不足以证明三路有效。新视觉保护仅在消息到达时检查有效性，不负责发布断流告警。

视觉 `Odom/ResetCountdown=3` 启用丢失后自动重建跟踪；不能假定丢失期间运动已被补回。长时间失效、视觉重置和坡道场景仍需单独回放/实测，保持原有定位与安全许可链。

## 隔离测试结果

使用已安装的 Jazzy / robot_localization 3.8.3，独立 `ROS_DOMAIN_ID=171`，两个真实 EKF 接收相同的合成观测，禁用测试节点 TF 输出，不启动硬件、不发送控制命令。视觉协方差使用保护后的下限值；预处理另由单元测试验证，测试未包含真实相机图像或串口。

场景：先静止 3 秒，随后以 0.5m/s 平直移动，视觉延迟 0.8 秒；视觉、IMU、轮侧依次各停发 3 秒并恢复；之后轮侧在真实 0.5m/s 时误报 0.8m/s 两秒；最后真实停车且三路同时停发两秒。

| 指标 | 旧配置 | 修改后 |
| --- | --- | --- |
| 稳态直行平均 x 误差 | 0.3760m | 0.0024m |
| 视觉中断窗口最大 x 误差 | 0.3692m | 0.0007m |
| IMU 中断窗口最大 x 误差 | 0.3932m | 0.0016m |
| 轮侧中断窗口最大 x 误差 | 0.3946m | 0.0016m |
| 同向滑移窗口最大 x 误差 | 0.2920m | 0.3659m |
| 全断流窗口最大 x 误差 | 0.3325m | 0.8017m |

两组时间戳均递增、位置有限；修改后全程最大相邻 x 变化约 0.2121m，说明滑移及恢复时仍可能明显修正，并非所有场景都平滑。全断流时修改后末次 vx 仍约 0.3438m/s，不能由“/odom 还在刷新”推出已经停车。旧配置的延迟偏差与部分打滑误差会相互抵消，某段误差更小不代表处理正确。

毫米级数字只表示理想合成观测下延迟补偿的效果，不代表实车定位精度。以上单路中断结果只覆盖短时平直运动，不包含坡道、急转、噪声、长时间失效和重定位。

复现（在 Jazzy 容器内，工作区 `/workspace`）：

```bash
source /workspace/install/setup.bash
cd /workspace
ROS_DOMAIN_ID=171 ROS_LOCALHOST_ONLY=1 RUN_EKF_INTEGRATION=1 \
  python3 -m pytest -q -s src/robot_navigation/test/test_state_estimation_integration.py
```

测试将对照指标写入 pytest 临时目录的 `report.json`；构建、launch 解析和其余单元测试应按仓库要求另行执行。
