# 两关节固件通信、标定与测试

更新日期：2026-11-19。对应文本API 0.5，参数格式见[硬件API](hardware_api.md)。本文件是操作步骤，不代表其中的运动、超时和联动测试已经完成。

当前源码已按用户要求改为U免零位/方向/中立标定，默认中立1500µs；上电、X、超时输出默认或已保存的自定义中立。旧配置中立未启用时初始化回退1500µs，R仍要求零位/方向标定，真实故障和传感器检查保留。master关节1不再受从板离线联锁或总线看门狗影响，slave自身失联停止保留；包含关节2的运动命令仍要求在线。停止时故障2不再阻止U，PWM运行中不合成该故障；未完整标定时不启用依赖方向映射的限位制动。以下实机零位记录描述改动前固件，不能将其PWM=0/neutral_valid=0套用到新固件。新行为尚未烧录验收，100ms回中立不等于物理断动力。

## 0. 默认中立与停止行为

历史2026-11-16已通过USB只读确认第二块板为`$info ARM_NODE 2`、版本0.2；其AS5600原始值最近约2119、电流ADC3678、温度ADC4095，尚未标定，PWM=0。这些数字不是应直接写入的零位或电流/温度物理值。

两轴默认中立为1500µs，上电和停止时输出该值。U每次有效100ms，到期回到中立；X立即清除运动目标并回中立，不是回零或切断动力。1500µs若不适合实际舵机，100ms到期也不保证物理停转。测试时需能独立断动力，并确认当前机械位置和允许行程。

0.5延续移除J查询/设置，不再通过J试转或测中立；速度、加速度和中立初始参数位于固件include/arm_config.h，旧NVS内部参数继续兼容。主从板及工具均须升级0.5，R状态为“编号、raw、角度、弧度、电流、PWM、状态、故障、模式”，不返回速度和两个时间字段；以下“实机零位记录”为改动前固件的历史数据和操作，不是0.5操作步骤。0.5尚未烧录或实机验收。

2. 退出PlatformIO串口监视器及其他占用端口的软件。不要在普通Shell直接输入R1；下面脚本是按行串口终端。
3. 在Mac终端执行（端口用`ls /dev/cu.usbmodem*`的实际结果）：


## 2. 只读检查双板通信

在上述串口终端逐条输入：

```text
$info
$version
R
$raw 1
$raw 2
A1
A2
P1
P2
H1
H2
```

通过条件：

- `$info ARM 2 1 2`表明USB接的是master，但这个名单本身不证明关节2在线。
- `$raw 2 <有效0～4095原始角度> ...`、`A2`和`P2`有正常回包，才能证明master下行、slave接收及Q2门控回包链路实际工作。
- 新固件未标定停止时可返回fault=2、角度NA和默认中立PWM=1500；U不因未标定被拒绝。fault=5或`!$raw TIMEOUT`是通信问题，两者不能混淆。
- AS5600 raw=-1且持续不恢复：检查磁铁、传感器供电、SCL/SDA；不是盲目clear或发送运动命令。

若USB返回`$info ARM_NODE 2`，仍接在第二板，需接回master。若master能查1不能查2，先核对slave环境、BUS两信号线、共地和供电，再查Q2的TX_EN/波形；不通过提升波特率或去掉CRC绕过问题。

连续只读测试另开一次脚本即可（先退出交互，数据仍未保存时注意重新打开可能复位）：

```bash
~/.platformio/penv/bin/python ESP32/arm_joint/scripts/api_cli.py \
  --port /dev/cu.usbmodem2101 --command '$raw 1' --command '$raw 2' \
  --command R --repeat 200 --hz 20
```

约10秒，检查无TIMEOUT/重启，关节2应有有效raw和状态（龄期不再对外返回，内部仍检查）。脚本报错即停止；不能把未校准电流NA当成过流保护已通过。

## 3. 标定机械中位与编码器方向

保持舵机动力断开，人工将两关节放到希望定义的机械中位；不要强行反向掰动减速机构。每轴记录从固定视角看的正方向箭头，未来和机械臂模型保持一致。

查询`$raw 1`，将**本次中位**实际raw记作raw1；查询`$raw 2`记作raw2。填入如下命令，尖括号是占位符，不要原样发送：

```text
A1 <raw1> 1 1
A2 <raw2> 1 1
R
```

此处两个+1暂为候选方向，还不能据此开始PID。编码器方向若可在无动力且不损伤传动条件下验证，轻移几度沿正方向观察角度；正方向角度下降就将encoder_dir改为-1，零位raw不变。不能手动移动时，等中立确认后用小幅短脉冲验证。

`$zero 1/2`可重设当前零位，但只设置zero_valid，不替代A的方向确认。方向未验证时fault=2仍可能存在；U不受此标定提示阻止，R仍要求有效零位和方向。master查询R是缓存反馈，A后等待几十毫秒再读。

## 4. 默认中立与限时PWM检查

先查询R1，编号之后第一项为原始编码器读数；即使角度为NA，raw仍可有效。保持在允许行程内并能立即切断动力，再单次发送：

```text
U1 1600
R1
```

U1不要求零位/方向标定；每条只执行100ms，之后回默认1500µs。不要用连续J输出替代U；0.5对J返回CMD。另一方向可在当前机械条件允许时单次测试U1 1400。板端仍检查编码器有效性和真实故障，已设置零位的绝对越限检查保留。

需要观察较长时间时，显式以20Hz重复U；每次有效期独立，停止刷新后回中立。现有批处理工具结束会发X，不能用其证明100ms自动到期。raw和反馈只能确认编码器变化，精确PWM时序需要仪器测量。

## 5. 确认方向与保存零位

固定观察视角，明确关节正方向；将U引起的实际正反转与前后raw对照。恢复机械零位后重新核对raw，确定encoder_dir和motor_dir，再用A设置实测方向。不要直接把历史1962/1929或默认1/1当成拆装后的有效标定。

已核对零位及方向、编码器正常且处于允许角度范围时，可逐轴执行clear，再保存：

```text
$clear 1
$clear 2
$save 1
$save 2
```

单测master关节1时只执行对应轴命令，无需为关节2清故障；主轴不依赖从板在线。断电重启后查询A1/A2、P1/P2及R，核对零位、方向和默认中立；旧自定义中立仍按已有NVS读取。状态中角度之后为弧度，不是速度；不再返回剩余有效期或反馈龄期。角度模式需真实方向匹配后再测试，不把U免标定等同于R免标定。

## 无示波器时定位BUS超时

两板分别通过USB查询`$info`和自身`$raw`正常，但master查询`$raw 2`超时时，分别烧录包含`$bus`的新master/slave固件。该命令只查询USB当前连接板的UART累计计数，不转发、不发送电机命令，重新启动后计数归零。保持两板BUS相连，在两板USB终端各发送一次`$bus`，随后在master发送`$raw 2`，再分别查询`$bus`，比较增量；master后台也会持续轮询，所以不能要求只增加一帧。

| 观察到的增量 | 优先排查 |
| --- | --- |
| master的tx增长，slave的rx不增长 | 下行RX线、GPIO20对应及焊接；tx只证明UART完成发送 |
| slave的rx增长，frame不增长 | 下行数据、组帧时序或电平；bad只统计收到完整行后的CRC/封装失败 |
| slave的frame增长，hit不增长 | 目标ID、实际主从固件及请求内容 |
| slave的hit与tx增长，master的rx不增长 | Q2的G/S/D实际接法、TX_EN到GPIO7、TX_BUS与master接收路径 |
| master的rx增长，frame不增长或bad增长 | 回包信号电平、组帧及CRC |
| txerr增长 | UART发送未完成或驱动错误 |

slave发送路径为：收到完整请求→验证CRC和目标ID→GPIO7拉高→等待10µs→UART发送→等待TX_DONE→GPIO7拉低。正常回包使能仅持续数毫秒，万用表低读数或中间值不能证明没有拉高。计数同样不能代替对真实GPIO电平和串口波形的测量。

若slave的frame、hit、tx持续增加且bad=0，但master有rx而frame=0，已定位到回包方向，不能再归因于slave完全未收到命令。给master烧录包含`$busraw`的新固件即可保留slave当前诊断固件；在master上等待一秒，依次查询`$bus`、`$busraw`、`$busraw`，记录返回。原始数据为最近最多96字节的十六进制，不丢弃非法字符，窗口可能从帧中间开始，用于分析字节错误、分隔符及CRC；不要为了通过通信而关闭CRC校验。

2026-11-16用户回传数据含`0A 00 40`，即换行、额外NUL、下一帧起始符@；截获的222、223、295、296四帧CRC均正确。旧组帧器因帧外NUL进入丢弃到换行状态，导致下一帧有效回包丢失。已将UART改为遇@重新同步、忽略帧外字节，帧内非法字符仍拒绝，CRC和序号校验保留；USB文本输入仍采用原严格组帧器。真实数据回放复现旧实现0帧有效、新实现4帧有效，并测试帧内NUL不能被删除后接受。当时建议先只更新master，再用`$bus`确认frame/hit增长、用`$raw 2`和`R`验证实际通信；额外NUL的物理来源尚未测量确认。

后续实测frame增长、bad=0但hit仍为0，说明当前等待期间解码到的有效帧序号不匹配；R2曾有反馈龄期，表示启动后至少成功过一次。多次master接收总数为120的整数倍，与ESP-IDF 5.4 UART默认RX FIFO阈值120一致，因此推测短帧受空闲检测影响、滞留FIFO后成批交付。已将RX阈值显式配置为1字节，不增加15ms回包等待窗口、不放宽序号校验；`$bus`增加wait/seen/mismatch供验证。当时建议先仅更新master，再查询`$bus`、`$raw 2`、`R`，确认hit增长及从板在线；FIFO延迟推断仍需本轮实机结果验证。
