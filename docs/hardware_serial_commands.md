# 底盘硬件串口指令集

本文描述直接发送给 DMC0、DMC1、SE2 控制板的 ASCII 串口命令。DMC0 上的**双编码器直流减速电机
驱动四条大腿**，使用绝对编码器反馈角度，同时具有增量编码器；DMC1 上的**单增量编码器直流
减速电机驱动四个轮子**，使用增量编码器反馈速度和位置。SE2 控制头部与转向舵机、超声波和
输入输出。下文的单轴 `<id>` 是控制板电机 ID，多轴参数按 `$info` 返回的 ID 顺序排列。

这些命令绕过 ROS 运动学、超声波避障、轮速看门狗和关节保护，只用于架空轮调试、控制板验收
和故障定位。文末区分了备忘录中的 vctrl JSON 接口与控制板原生串口接口。

## 1. 通信参数

| 项目 | 值 |
|---|---|
| 波特率 | 115200 |
| 数据格式 | 8N1，无流控 |
| 命令/响应结束符 | `\n` |
| 控制线 | 打开串口后拉高 DTR、RTS |
| 控制板 | DMC0：四个双编码器大腿电机；DMC1：四个单增量编码器轮电机；SE2：六路舵机，协议支持十路超声波，当前实车接入八路 |

每条命令前应清空串口输入残帧。响应以命令字符或 `$` 开头；以 `!` 开头表示错误。

直接串口调试须由独占串口的终端完成；仓库内已移除通用串口终端。发送命令时应使用 LF 换行，并核对 `$info` 返回的板卡身份。

## 2. 使用前准备

同一时刻只能有一个程序访问控制板：

```bash
sudo systemctl stop vctrl.service
# 同时停止正在运行的 ros2 launch
fuser /dev/ttyACM0 /dev/ttyACM1 /dev/ttyACM2
```

不要根据 `/dev/ttyACM*` 编号猜身份。USB 重枚举后编号会变化，必须逐个发送 `$info`。

## 3. 控制板识别

命令：

```text
$info\n
```

返回示例：

```text
$info DMC 4 0 1 2 3
$info DMC 4 4 5 6 7
$info SE2
```

| 返回 | 身份 |
|---|---|
| DMC，首个电机 ID 为 0 | DMC0，四腿控制器 |
| DMC，首个电机 ID 为 4 | DMC1，四轮驱动控制器 |
| SE2 | 头部、四轮转向和超声波控制器 |

`$info DMC` 返回的四个 ID 同时决定多轴命令的参数和响应顺序；不要将 DMC0 的 `R` 角度命令
用于轮电机，或将 DMC1 的 `S`/`T` 速度、编码器位置命令用于大腿电机。

## 4. DMC1 四轮驱动

四轮顺序：`[左前 FL, 右前 FR, 左后 RL, 右后 RR]`。

### 4.1 查询编码器参数

```text
I4 \n
I5 \n
I6 \n
I7 \n
```

返回：

```text
I <电机ID> <每圈计数CPR> <编码器方向>
```

查询之间至少间隔 20ms。CPR 和方向必须使用板端返回值，不能写死。

### 4.2 查询四轮状态

```text
S \n
```

返回一行 4 组数据：

```text
S <tps0> <encoder0_hex> <current0_mA> ... <tps3> <encoder3_hex> <current3_mA>
```

### 4.3 设置四轮速度

2026-09-27 实车复测：多轴 `S` 仅左前轮响应；同一轮改用 `S5`、`S6` 单轴命令后，
右前和左后均能转动。ROS 硬件插件因此逐轮发送 `S4`～`S7`，并核对每轴响应。
以下多轴语法保留作协议参考，不用它判断当前实车的单轮驱动故障。

```text
S5 <目标速度_tick/s> <运行时间_ms>\n
```

单轴响应：`S5 <当前速度_tick/s> <编码器_hex> <电流_mA> <错误码>`；其他轮 ID 为 4、6、7。
板端 `J4..J7` 的单条运行时间上限实测为 1000ms。停车逐轮发送 `S4 0 500` 至 `S7 0 500`。

```text
S <tps0> <tps1> <tps2> <tps3> <duration_ms>\n
```

参数单位是编码器 tick/s，不是 m/s 或 rad/s：

```text
ticks_per_second = linear_mps * CPR / (pi * wheel_diameter_m)
wheel_diameter_m = 0.110
```

架空轮低速测试：

```text
S 100 100 100 100 500\n
```

停车：

```text
S 0 0 0 0 0\n
```

首次测试必须使用较短的非零 `duration_ms`，并先确认四轮正方向。直接串口控制没有 ROS 宿主
500ms 看门狗。

本次单轴 `S4/S5/S6` 在约 100～300tick/s 无输出，约 400tick/s 开始转动。右侧轮的
板端 tps 符号与 ROS 正轮速相反，绘制轮速曲线时需换算。右后 `D7 10%` 仅约
0.016rad/s、峰值 2167mA；`S7 400tick/s` 短脉冲触发 2200mA 软件停车。
用户给定的瞬时边界为 3000mA、最长 2s，右后轮未取得安全稳态速度，不能直接跳到 `D7 100%`。
2026-09-28 继续逐级测试右后 D12%～30%：D20%/600ms 的轮速波动很大，
D30%/300ms 采样到 2875mA 并触发 2800mA 软件停车。D7 100% 尚未执行。
左前/右前/左后的 D 已测稳态速度分别扩展到 1.335/1.041/0.964rad/s；
对应 S 单轴曲线、电流及原始数据见 `motion_control_commands.md`。
本机 `I4..I7` 为 11600 CPR、方向 `[-1,+1,-1,+1]`。S 的目标符号保持命令原值，
板端右轮实测 tps 在正向 S 目标下为负；换算 ROS 轮速时实测 tps 乘
`-encoder_direction`。

### 4.4 设置增量编码器绝对位置目标

```text
T <target0_hex> <target1_hex> <target2_hex> <target3_hex>\n
```

`T` 是增量编码器计数坐标中的 32 位绝对目标，不是相对距离：

```text
delta = round(-distance_m / (pi * wheel_diameter_m) * CPR * encoder_direction)
target = uint32(current_encoder + delta)
```

必须先用 `S` 读取当前值，并用 `I4..I7` 读取 CPR 和方向。错误目标可能导致长距离运动，日常
定距应使用 ROS `/execute_wheel_motion` Action。

## 5. DMC0 四腿控制

顺序：`[左前 FL, 右前 FR, 左后 RL, 右后 RR]`。

### 5.1 查询状态

```text
R \n
```

返回一行 4 组数据：

```text
R <angle0_x100> <speed0_deg_s> <current0_mA> ...
  <angle3_x100> <speed3_deg_s> <current3_mA>
```

角度是控制板原生定点角度，数值 100 表示 1°。

### 5.2 设置四腿角度

```text
R <raw_fl> <raw_fr> <raw_rl> <raw_rr>\n
```

ROS 关节角度换算：

```text
raw_fl = -degree_fl * 100
raw_fr = +degree_fr * 100
raw_rl = -degree_rl * 100
raw_rr = +degree_rr * 100
```

0° 示例：

```text
R 0 0 0 0\n
```

固件也支持单腿命令：`R0`、`R1`、`R2`、`R3`。直接控制会绕过姿态与过流保护，日常应使用
ROS `/body_balance/set`。

## 6. SE2 舵机与超声波

六路舵机顺序：

```text
[head_yaw, head_pitch, steer_fl, steer_fr, steer_rl, steer_rr]
```

八路超声波顺序：

```text
[front_left, front_center, front_right, right,
 rear_right, rear_center, rear_left, left]
```

### 6.1 查询 ADC 和超声波

```text
f    \n
```

返回：

```text
f <adc0> ... <adc5> <range0_mm> ... <range7_mm>
```

ADC 是 12 位环形编码器原始值；距离单位 mm。当前主机只接受 30~2500mm，0~20mm 常见于
无效回波或探头振铃，不能直接当成真实障碍。

### 6.2 设置六路舵机 PWM

```text
U <pwm0> <pwm1> <pwm2> <pwm3> <pwm4> <pwm5>\n
```

范围 500~2500；停止/中性值 1500。全部停止：

```text
U 1500 1500 1500 1500 1500 1500 \n
```

`U` 发送的是舵机 PWM 脉宽（单位 µs），不是角度。SE2 不在板内完成位置闭环；ROS 插件和 `hw_ctrl` 都是在主机读取
`f` 的 ADC 后执行 PID，再周期发送 `U`。禁止长时间发送非 1500 固定值，否则会撞机械限位或
堵转烧毁。

## 7. DMC 原生命令参考

以下语法摘自硬件命令备忘录。方括号表示可选参数，示例中的 `\n` 是串口结束符，使用上面的
按行终端时只需按回车。`f_int16` 为数值乘以 100 后的 `int16`，例如角度 1° 发送 `100`；
`int32` 编码器值以十六进制文本传输。查询时省略可选目标参数。

| 命令 | 适用电机 | 请求格式 | 返回格式 |
|---|---|---|---|
| `R<id>` | DMC0 双编码器大腿 | `R<id> [<目标角度_f_int16>]` | `R<id> <当前角度_f_int16> <当前角速度_f_int16> <电流_mA_int16> <错误码_int16>` |
| `S<id>` | DMC1 单增量编码器轮子 | `S<id> [<目标速度_tick/s_int16>] [<运行时间_ms_int16>]` | `S<id> <当前速度_tick/s_int16> <编码器值_hex_int32> <电流_mA_int16> <错误码_int16>` |
| `T<id>` | DMC1 单增量编码器轮子 | `T<id> [<绝对目标编码器值_hex_int32>]` | `T<id> <当前速度_tick/s_f_int16> <编码器值_hex_int32> <电流_mA_int16> <错误码_int16>` |
| `D<id>` | DMC 电机单步调试 | `D<id> [<PWM占空比_±0~100_int16>] [<运行时间_ms_int16>]` | `D<id> <绝对编码器_mV_uint16> <增量编码器值_int32> <电流_mA_int16>` |
| `I<id>` | 增量编码器配置 | `I<id> [<每圈脉冲数_int16>] [<顺时针增量方向_int16>]` | `I<id> <每圈脉冲数_int16> <方向_int16>` |
| `A<id>` | 绝对编码器配置 | `A<id> [<每度电压增量_mV_f_int16>] [<零点电压_mV_int16>] [<最小角度_int16>] [<最大角度_int16>]` | `A<id> <每度电压增量_mV_f_int16> <零点电压_mV_int16> <最小角度_int16> <最大角度_int16>` |
| `J<id>` | 关节配置 | `J<id> [<工作模式_int16>] [<最低PWM_int16>] [<最高PWM_int16>] [<单条命令最长运行时间_ms_int16>]` | `J<id> <工作模式_int16> <最低PWM_int16> <最高PWM_int16> <最长运行时间_ms_int16>` |
| `P<id>` | PID 配置 | `P<id> [<Kp_f_int16>] [<Ki_f_int16>] [<Kd_f_int16>] [<误差精度_f_int16>] [<重力补偿方向_int16>]` | `P<id> <Kp_f_int16> <Ki_f_int16> <Kd_f_int16> <误差精度_f_int16> <重力补偿方向_int16>` |

多轴命令由 `$info` 的四个 ID 对应四组参数：

| 命令 | 请求格式 | 返回格式 |
|---|---|---|
| `R` | `R [<目标角度0> <目标角度1> <目标角度2> <目标角度3>]` | `R <角度0> <角速度0> <电流0> ... <角度3> <角速度3> <电流3>` |
| `S` | `S [<目标速度0> <目标速度1> <目标速度2> <目标速度3>] [<运行时间_ms>]` | `S <速度0> <编码器0_hex> <电流0> ... <速度3> <编码器3_hex> <电流3>` |
| `T` | `T [<绝对目标编码器值0_hex> ... <绝对目标编码器值3_hex>]` | `T <进度_0~100或负错误码> <距目标计数0> ... <距目标计数3>` |
| `Tr` | `Tr [<相对目标编码器增量0> ... <相对目标编码器增量3>]` | 备忘录列为 `T <速度0> <编码器0_hex> <电流0> ... <速度3> <编码器3_hex> <电流3>` |
| `D` | `D`（只读四轴状态） | `D <绝对编码器0_mV> <增量编码器0> <电流0> ... <绝对编码器3_mV> <增量编码器3> <电流3>` |

`R` 和 `S` 多轴目标为 `0x7FFF` 时，备忘录说明对应轴会忽略该目标；其 `S` 段将速度目标
误称为“目标角度”，这里按 `S` 的速度命令语义记录。备忘录对 `Tr` 返回格式
和 `T` 多轴返回格式的记载不同；目前 ROS 插件只向 DMC1 发送 `T` 绝对目标，未验证 `Tr`
及多轴 `T` 的返回，不应据此编写自动解析或在实车直接试动。

其他 DMC 板级命令：

| 命令 | 用途与返回 |
|---|---|
| `Ir` | 将增量编码器复位到中间值；返回 `Ir <中间值>`。会改变位置参考，运行中不可使用。 |
| `L` | 读取最近马达控制日志；返回 `L <最近的日志>`。 |
| `$load`、`$save`、`$reset` | 加载、保存、复位配置；返回 `$load/$save/$reset <0:成功>`。会改变板端状态。 |
| `$debug` | 备忘录列出的调试命令；返回字段未说明。 |
| `$id <起始ID>` | 设置起始 ID；返回 `$id <关节数量> <ID0> ... <ID3>`。会改变主机对板的识别。 |

## 8. SE2 原生命令参考

| 命令 | 请求格式 | 返回格式 |
|---|---|---|
| 系统 | `$info`、`$reset` | `$info SE2`；`$reset <0:成功>` |
| 单路舵机 | `U<index> <脉宽_us>`，index 为 0~5，脉宽通常为 500~2500 | `U<index> <脉宽_us>` |
| 头部双路 | `U <脉宽0_us> <脉宽1_us>` | 备忘录未列出多路返回格式 |
| 转向四路 | `U <脉宽2_us> <脉宽3_us> <脉宽4_us> <脉宽5_us>` | 备忘录未列出多路返回格式 |
| 单路超声波 | `E<index>`，index 为 0~9 | `E<index> <距离_mm_uint32>` |
| 全部超声波 | `E` | `E <距离0_mm> ... <距离9_mm>`，备忘录标为 `int16` |
| 输出开关 | `K0 <1或0>` | `K0 <当前状态>` |
| 全部状态，电压 | `F` | `F <ADC电压0_mV> ... <ADC电压5_mV> <距离0_mm> ... <距离9_mm>` |
| 全部状态，原始 ADC | `f` | `f <ADC原始读数0> ... <ADC原始读数5> <距离0_mm> ... <距离9_mm>` |

`U<index>` 中脉宽 `0x7FFF` 表示忽略该通道。备忘录列出 10 路超声波协议字段，但当前实车
和 ROS 插件只接入、解析前 8 路；不能把第 8、9 路视为已安装的传感器。ROS 插件实际使用
六路 `U` 命令，并从 `f` 响应读取 6 路 ADC 和前 8 路距离。

## 9. 最小安全测试顺序

1. 停止 ROS 和 `vctrl.service`，确认串口独占。
2. 架空四轮，逐端口发送 `$info`，记录 DMC0、DMC1、SE2 路径。
3. 依次执行 `I4..I7`、`S`、`R`、`f`，先做只读检查。
4. DMC1 用小 tps、短 duration 测试四轮，立即停车。
5. 没有主机 PID 时，不测试 SE2 位置运动。
6. 关闭串口前再次发送 DMC1 和 SE2 停止命令。

## 10. 故障判断

| 现象 | 优先检查 |
|---|---|
| `$info` 无返回 | DTR/RTS、波特率、串口占用、USB 重枚举 |
| 返回以 `!` 开头 | 命令格式、参数数量或范围 |
| 相同 tps 下单轮速度低且电流高 | 机械堵转、电机、驱动器、线束 |
| 轮子实际正常但 tps/编码器异常 | 编码器、CPR/方向参数、DMC 通道 |
| 舵机持续出力 | PID、零位、方向、ADC；立即发送全部 1500 |
| 超声波返回 0~20mm | 无效回波、串扰、探头或通道问题 |

当前实车曾观察到右后轮启动明显迟滞且电流偏高。直接串口复测时应重点对比 DMC1 第四组
tps、encoder 和 current，并通过交换电机/驱动通道区分机械、电机、驱动与编码器故障。

## 11. 与 vctrl/MQTT 指令的关系

备忘录第三节的 `/cmd_vel`、`/joint`、`/cmd_mov`、`/reset_odom`、`/get_params` 是
vctrl 的 JSON 命令，不是直接发往 DMC 或 SE2 的 ASCII 串口命令。vctrl 会完成 Twist 运动学、
关节换算、舵机 PID 和串口转发。本文描述它下面的控制板原生串口协议；vctrl、ROS 和原生
串口终端不能同时连接控制板。
